Why TLS 1.3 shows 3 ciphers (nmap) vs 1 cipher (openssl): This is expected and is not a cap issue. nmap probes each TLS 1.3 cipher suite individually and reports all that the server accepts. 4. Findings & Verification Summary

Protocol Compliance

  • github.com — TLS 1.2 + 1.3 only. Deprecated versions correctly blocked. ✓ Best practice.
  • google.com / cloudflare.com — TLS 1.0/1.1 still enabled for legacy clients. Ciphers on those versions are rated NOT_APPROVED (correctly flagged).
  • badssl.com legacy endpoints — Intentionally misconfigured. Each host serves exactly one deprecated protocol — all detected correctly by both backends.

Backend Parity (IANA normalisation working)

  • TLS 1.2 cipher sets: identical across backends for all 6 targets (after IANA normalisation).
  • TLS 1.0/1.1: nmap finds 1 extra cipher on google/cloudflare — minor cipher-support list difference between nmap's internal OpenSSL and system OpenSSL, not a bug.
  • TLS 1.3: nmap finds all 3 supported ciphers; openssl reports 1 (server preference). Both report SUPPORTED. Compliance ratings identical on common ciphers.
  • All openssl_name fields in JSON populated correctly where backend returned OpenSSL shorthand.

Proxy Support (unaffected)

  • --proxy http://... — openssl backend only (-proxy flag to s_client).
  • --socks-proxy socks5://... — both backends (openssl -socksport; nmap --proxies).
  • HTTP proxy with nmap prints a warning and continues; SOCKS proxy works with both backends unchanged.
